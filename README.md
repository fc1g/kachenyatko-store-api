# Kachenyatko Store API

REST API for a small handmade toy shop.

### Stack

- **Go** with [chi](https://github.com/go-chi/chi) router and [httprate](https://github.com/go-chi/httprate) for rate limiting
- **PostgreSQL** via [pgx](https://github.com/jackc/pgx); queries generated with [sqlc](https://sqlc.dev), migrations with [goose](https://github.com/pressly/goose)
- **Cloudflare R2** (S3-compatible) for toy images, via AWS SDK v2
- **Telegram Bot API** via [go-telegram/bot](https://github.com/go-telegram/bot) for new order notifications
- **JWT** (EdDSA / Ed25519) via [golang-jwt](https://github.com/golang-jwt/jwt) in an HttpOnly cookie, passwords hashed with [argon2id](https://github.com/alexedwards/argon2id)
- [caarlos0/env](https://github.com/caarlos0/env) for configuration, [validator](https://github.com/go-playground/validator) for validation, [zerolog](https://github.com/rs/zerolog) for logging
- **Swagger / OpenAPI** docs generated with [swag](https://github.com/swaggo/swag)

### Prerequisites

- [Go](https://go.dev/dl/) 1.27.1+ (see `go.mod`)
- [Docker](https://docs.docker.com/get-docker/) with Compose v2 (`docker compose`), used to run PostgreSQL locally
- `make`
- [goose](https://github.com/pressly/goose) v3 for database migrations
- [sqlc](https://sqlc.dev) v1.31+ to generate query code from SQL (needed only when you change `db/queries` or `db/migrations`)
- [air](https://github.com/air-verse/air) for hot reload in development (optional: `go run ./cmd/server` also works)
- A Cloudflare R2 bucket with an API token (Object Read & Write), required for image uploads
- A Telegram bot token from [@BotFather](https://t.me/BotFather) and the ID of the chat that receives order notifications (the bot must be a member of that chat)
- `openssl` to generate the Ed25519 key that signs access tokens

### Quick start

```sh
# 1. Clone and enter the project
git clone https://github.com/fc1g/kachenyatko-store-api.git
cd kachenyatko-store-api

# 2. Create a local config from the example
cp .env.example .env

# 3. Generate the token signing key and put the output into .env as AUTH_SIGNING_KEY
openssl genpkey -algorithm ed25519 -out private.pem
base64 < private.pem | tr -d '\n'

# 4. Start PostgreSQL (keep this terminal open, or use `docker compose up -d`)
make up

# 5. In a new terminal: apply database migrations
make migrate

# 6. Create the admin user (see "Authentication" below)
make admin ADMIN_EMAIL=owner@example.com ADMIN_PASSWORD='your-password'

# 7. Run the server with hot reload (requires air)
make dev
# or without air:
go run ./cmd/server
```

Check that it works (`.env.example` sets `PORT=3001`):

```sh
curl http://localhost:3001/livez    # {"status":"OK"}
curl http://localhost:3001/readyz   # {"status":"OK"} when the database is reachable
```

API docs: http://localhost:3001/swagger/index.html

### Project structure

```
cmd/
  server/          HTTP server entry point
  create-admin/    one-off command that creates the admin user
db/
  migrations/      goose migrations (also the schema for sqlc)
  queries/         SQL queries for sqlc
internal/
  app/             wiring: builds dependencies, runs and stops the server
  router/          all routes, auth and rate limit rules in one place
  config/          environment variables → Config

  category/  toy/  order/  user/  session/  health/
                   features: handler, service, responses and error mapping each

  auth/            JWT, password hashing, auth middleware, cookie
  database/        connection pool, transactions, PostgreSQL error helpers
  database/sqlc/   generated by sqlc, do not edit
  httpx/           JSON, query params, error responses, request logging
  apperr/          transport-independent error codes
  validation/      struct validation with readable messages
  storage/  telegram/  logging/
docs/              generated Swagger, do not edit
```

### Configuration

The server reads its configuration from environment variables. In development they are loaded from `.env` if the file exists; in production, set them in the environment directly.

| Variable                   | Required | Default                       | Description                                                   |
|----------------------------|----------|-------------------------------|---------------------------------------------------------------|
| `ENVIRONMENT`              | yes      | —                             | `development` or `production`                                 |
| `HTTP_HOST`                | no       | `127.0.0.1`                   | Listen address; `0.0.0.0` inside Docker. |
| `PORT`                     | no       | `3001`                        | HTTP port                                                     |
| `HTTP_CLIENT_IP_HEADER`    | no       | — (TCP connection address)    | Header with the real client IP from a trusted proxy; `CF-Connecting-IP` behind Cloudflare Tunnel. Never set it if the API port is reachable directly |
| `HTTP_READ_HEADER_TIMEOUT` | no       | `5s`                          | Time to read request headers                                  |
| `HTTP_READ_TIMEOUT`        | no       | `10s`                         | Time to read the whole request (image uploads get 3 minutes)  |
| `HTTP_WRITE_TIMEOUT`       | no       | `10s`                         | Time to write the response (image uploads get 3 minutes)      |
| `HTTP_IDLE_TIMEOUT`        | no       | `60s`                         | Keep-alive idle timeout                                       |
| `HTTP_SHUTDOWN_TIMEOUT`    | no       | `10s`                         | Whole graceful shutdown: in-flight requests and pending Telegram notifications |
| `LOG_LEVEL`                | yes      | —                             | `trace`, `debug`, `info`, `warn`, `error`, `fatal` or `panic` |
| `LOG_PRETTY`               | no       | `true` in dev, otherwise `false` | Human-readable console logs instead of JSON                |
| `DB_URL`                   | yes      | —                             | PostgreSQL connection string                                  |
| `DB_PING_TIMEOUT`          | no       | `2s`                          | Database ping timeout (startup and `/readyz`)                 |
| `R2_ENDPOINT`              | yes      | —                             | `https://<account-id>.r2.cloudflarestorage.com`               |
| `R2_ACCESS_KEY_ID`         | yes      | —                             | R2 API token access key                                       |
| `R2_SECRET_ACCESS_KEY`     | yes      | —                             | R2 API token secret                                           |
| `R2_BUCKET_NAME`           | yes      | —                             | Bucket for toy images                                         |
| `R2_PUBLIC_URL`            | yes      | —                             | Public base URL of the bucket                                 |
| `TELEGRAM_ACCESS_TOKEN`    | yes      | —                             | Bot token from @BotFather                                     |
| `TELEGRAM_CHAT_ID`         | yes      | —                             | Chat for order notifications (negative for groups)            |
| `TELEGRAM_SEND_TIMEOUT`    | no       | `10s`                         | Timeout for sending a notification                            |
| `SITE_URL`                 | yes      | —                             | Storefront URL, used for toy and admin links in Telegram notifications |
| `AUTH_SIGNING_KEY`         | yes      | —                             | Base64 of the Ed25519 private key in PEM format               |
| `AUTH_ISSUER`              | yes      | —                             | `iss` claim written to and checked in access tokens           |
| `AUTH_TOKEN_TTL`           | no       | `24h`                         | Access token lifetime, at most `24h`                          |

### Deployment

The API is meant to run behind **Cloudflare Tunnel → nginx**, with nginx serving the storefront and proxying the API from the **same origin** (e.g. `https://shop.com` and `https://shop.com/api/...`). Because of that the API has no CORS: browsers only call it from its own origin. In development, use the dev server proxy of the frontend (e.g. Vite `server.proxy`) for the same effect.

The API and nginx ports must not be reachable from the internet, otherwise the client IP used for rate limiting can be spoofed. Network setup, nginx and cloudflared configs, Docker notes and post-deploy checks are in [INFRASTRUCTURE.md](INFRASTRUCTURE.md).

On shutdown (`SIGINT`/`SIGTERM`) the server stops accepting requests, waits for in-flight ones and for pending Telegram notifications, all within `HTTP_SHUTDOWN_TIMEOUT`. Give the process manager more time than that (e.g. Docker `stop_grace_period: 15s`; the Docker default of 10s is too tight).

### Authentication

The API has a single user: the **admin**, the owner of the shop. Customers do not sign up: they browse the catalog and place orders without an account, so the storefront stays as simple as possible.

That is why there are only login and logout routes and no registration:

| Route          | Auth | Description                                                       |
|----------------|------|-------------------------------------------------------------------|
| `POST /login`  | no   | Checks email and password, sets the `access_token` cookie         |
| `POST /logout` | no   | Clears the `access_token` cookie, returns `204`                   |
| `GET /me`      | yes  | Returns the logged-in user; the admin panel calls it on page load |

**Public** routes: reading categories, toys and toy images, creating orders, login, logout, health checks and Swagger. **Admin only**: creating, updating and deleting categories, toys and images; reading and updating orders; everything under `/users`.

#### Access token

- A JWT signed with Ed25519, sent as an `HttpOnly`, `SameSite=Lax` cookie (`Secure` in production). The storefront and the API share one origin, so the browser sends the cookie automatically.
- It lives for **1 day** (`AUTH_TOKEN_TTL`, up to `24h`). There are no refresh tokens: the admin just logs in again. Logout only deletes the cookie, so the token itself stays valid until it expires: the route exists mainly for convenience in development and testing.
- Changing `AUTH_SIGNING_KEY` invalidates all tokens.

#### Creating the admin

There is no HTTP route that creates users. Create the admin once with the `create-admin` command (it needs only `DB_URL`, `ADMIN_EMAIL` and `ADMIN_PASSWORD`; the password must be 8–128 characters):

```sh
make admin ADMIN_EMAIL=owner@example.com ADMIN_PASSWORD='your-password'
```

If a user with this email already exists, the command fails and changes nothing.

#### Room to grow

A single admin is a temporary solution. If the project grows and needs it, roles will be added and customers will get more features.

### Limits

| What                     | Limit                                                                 | Response |
|--------------------------|-----------------------------------------------------------------------|----------|
| Login attempts           | 5 per minute per client IP                                            | `429`    |
| New orders               | 10 per 10 minutes per client IP, shared by `POST /orders` and `POST /toys/{id}/orders` | `429` |
| JSON request body        | 1 MB                                                                  | `413`    |
| Toy images               | JPEG, PNG or WebP, up to 5 MB each, at most 5 per toy                 | `400` / `409` / `413` |
| Pagination               | `limit` defaults to 9, at most 100; `offset` defaults to 0            | `400`    |

Every error response has the same shape:

```json
{ "code": "NOT_FOUND", "message": "toy not found" }
```

`code` is one of `INVALID`, `UNAUTHORIZED`, `FORBIDDEN`, `NOT_FOUND`, `CONFLICT`, `PAYLOAD_TOO_LARGE`, `TOO_MANY_REQUESTS`, `INTERNAL`.

### Make commands

| Command               | Description                                    |
|-----------------------|------------------------------------------------|
| `make up`             | Start PostgreSQL in Docker (foreground)        |
| `make down`           | Stop and remove the containers; data is kept   |
| `make clean`          | Stop containers and **delete volume**          |
| `make dev`            | Run the server with hot reload (air)           |
| `make migrate`        | Apply all pending migrations                   |
| `make migrate-down`   | Roll back the last applied migration           |
| `make migrate-status` | Show which migrations are applied              |
| `make psql`           | Open a `psql` shell in the database container  |
| `make admin`          | Create the admin user (see "Authentication")   |
| `make sqlc`           | Regenerate `internal/database/sqlc`            |
| `make swag`           | Regenerate Swagger docs in `docs/`             |

All commands read variables from `.env`, so create it first (`cp .env.example .env`).
